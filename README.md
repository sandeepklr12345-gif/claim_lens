# ClaimLens

![CI](https://github.com/sandeepklr12345-gif/claim_lens/actions/workflows/blank.yml/badge.svg)

An explainable agent that audits **health-insurance claim rejections (India)**.
Input: a rejection letter and a policy document. Output: a verdict (with an abstain option), the
best-matching policy clause with token-level **Integrated Gradients** attributions, an LLM
explanation checked against those attributions (**faithfulness**), and a template appeal draft.

> **Decision support, not legal advice.** Explainable AI mini project, Phase 1 (prototype built for
> a 5 Nov 2026 presentation). Author: [TODO: name, USN].

**Research question:** does checking an LLM's explanation against Integrated Gradients attributions,
and asking it to revise, make the explanation more faithful?
**Short answer from this prototype:** only slightly (mean AAS 0.200 → 0.233 on 20 synthetic cases,
random-span chance level 0.171). See [Results](#results) and [Limitations](#limitations).

## How it works

```
letter ─ parse ─ retrieve ─ match ─ explain_reflect ─ verdict ─ draft
         (LLM)   BM25+dense  cross-    LLM explanation     tau_high/   template
                 RRF, top 10 encoder   cites clause spans; tau_low,     appeal
                 → re-rank   score     IG attributions →   abstains     (if NOT_
                 → top 3                AAS; revise < 0.6                SUPPORTED)
```

- **Policies:** two public wordings (Care Supreme, HDFC ERGO Optima Secure), chunked along clause
  numbers (`data/policies/`, sources in `data/policies/SOURCES.md`).
- **Matcher:** pretrained `cross-encoder/ms-marco-MiniLM-L-6-v2` (no fine-tuning in Phase 1).
- **Attribution:** Captum `LayerIntegratedGradients` on the embedding layer, 50 steps, pad baseline.
- **AAS (Attribution Alignment Score):** share of positive IG mass that falls inside the spans the
  explanation cites. Below 0.6 the agent sends feedback (influential words not cited, cited words
  that did not matter) and asks for a revision, up to 2 rounds, keeping the best.
- **LLM:** local Ollama (`qwen2.5:7b`). No paid API calls.
- **Agent:** linear LangGraph. Tools are served by two **MCP servers** (`policy-search`,
  `explainer`) over stdio; `--mcp` makes the agent call them, the default calls the same functions
  in-process.

## Run it (Windows, PowerShell)

Needs Python 3.11, an NVIDIA GPU is optional, [Ollama](https://ollama.com) running locally.

```powershell
git clone https://github.com/sandeepklr12345-gif/claim_lens.git ; cd claim_lens
py -3.11 -m venv .venv ; .\.venv\Scripts\Activate.ps1      # any venv location works
pip install torch --index-url https://download.pytorch.org/whl/cu128   # CUDA build; CPU also works
pip install -r requirements.txt
ollama pull qwen2.5:7b
python -c "import torch; print(torch.cuda.is_available())"
```

If `Activate.ps1` is blocked: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once.
The first run downloads two small Hugging Face models (`BAAI/bge-small-en-v1.5`,
`cross-encoder/ms-marco-MiniLM-L-6-v2`).

**Demo (one case, prints verdict, initial and final explanation, AAS before and after):**

```powershell
python -m claimlens.agent.run --case data\cases\case_001.json          # in-process tools
python -m claimlens.agent.run --case data\cases\case_001.json --mcp    # through the MCP servers
```

**UI:** `streamlit run app\streamlit_app.py` (pick a sample case or paste a letter, press *Run audit*).

**Search a policy:** `python -m claimlens.rag.search "waiting period" --doc care_supreme`

**MCP servers (stdio):** `python -m claimlens.mcp_servers.policy_server` and
`python -m claimlens.mcp_servers.explainer_server` (test with MCP Inspector).

**Evaluation:** `python -m eval.run_all` (about 15 minutes with the 7B model; per-case results are
cached in `eval/results/e2e/`, so a rerun is fast) writes `eval/results/summary.md`.
**Tests:** `pytest -q -m "not model"` (unit, no GPU) and `pytest -q -m model` (needs models and Ollama).

## Results

All numbers come from `eval/results/` (full tables in `eval/results/summary.md`). **All data is
synthetic and small: 20 cases and 80 pairs, generated by the local LLM; labels are by construction
and only 5 were hand-checked** (3 sound, 1 questionable, 1 wrong; see `data/QA.md`).

| Component | Result |
|---|---|
| Retrieval Recall@3 (20 cases) | BM25 0.85, hybrid 0.80, hybrid + re-rank 0.90 (differences are within noise at n = 20) |
| Matcher on 80 pairs (held-out half) | accuracy 0.575, F1 0.653, ROC-AUC 0.627 |
| End-to-end verdict agreement | 13 / 20 (65%); always answering SUPPORTED gives 12 / 20 (60%) |
| Mean AAS, initial → after reflection | 0.200 → 0.233 (improved in 4 of 20 cases, unchanged in 16) |
| Mean AAS of random spans of the same size | 0.171 |

## Limitations

- **The matcher scores relevance, not support.** A NOT_SUPPORTED case is a wrong rejection written
  against a benefit clause that is highly relevant to the reason, so the cross-encoder scores it
  high. The agent answers SUPPORTED for 17 of 20 cases and verdict agreement is close to the
  majority baseline. Fine-tuning a matcher is a Phase 2 item.
- **Faithfulness gain is small.** Initial AAS is only slightly above random-span chance, and a 7B
  model often returns the same spans when asked to revise. AAS can also be raised just by quoting
  top-attributed words; comprehensiveness / sufficiency checks are not built yet.
- **Synthetic, noisy data.** Letters are short and generic, gold labels were not fully verified, and
  the verdict thresholds (0.8 / 0.4) were tuned on a stratified 10-case dev split and did not
  generalise: accuracy 0.70 on those 10 cases but 0.50 on the other 10.
- **CI covers lint and unit tests only** (GitHub Actions, no GPU, Ollama or models). Model-dependent
  tests run locally.
- The two policy PDFs come from third-party mirrors; check the UIN and version against the insurer.
- The appeal draft is a fixed template, not legal advice and not verified against the Insurance
  Ombudsman Rules.
